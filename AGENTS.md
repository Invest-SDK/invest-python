# Руководство для coding-агентов

Этот файл задаeт правила работы AI-агентов со всем репозиторием. Если задача
пользователя противоречит этому файлу, сначала следуйте задаче пользователя,
но не ослабляйте требования к безопасности токенов и торговых операций.

## О проекте

Репозиторий содержит Python SDK для T-Invest API. Поддерживаемая версия Python
указана в `pyproject.toml`; основной актуальный интерфейс находится в
`t_tech.invest.grpc`.

Перед изменением кода прочитайте:

1. `README.md` — установка и базовое использование;
2. `BREAKING_CHANGES.md` — переход со старого интерфейса на gRPC;
3. `docs/ai/README.md` — карта контекста для LLM;
4. `.agents/skills/t-invest-python-sdk-bot-builder/SKILL.md` — полный
   workflow, если
   задача связана с разработкой или ревью торговой программы;
5. относящиеся к задаче proto-файлы, модели, сервисы, тесты и примеры.

Для фактов об API локальный код и proto-файлы приоритетнее тестов,
`BREAKING_CHANGES.md`, документации, примеров, внешних статей и памяти модели.
Не придумывайте классы, enum, поля запросов или методы SDK: найдите их
определение в текущей версии репозитория.

## Карта репозитория

- `t_tech/invest/grpc/` — актуальные модели, сервисы и клиенты gRPC;
- `protos/t_tech/invest/grpc/` — исходные proto-контракты;
- `t_tech/invest/grpc/utils/clients.py` — `Client`, `AsyncClient`,
  `SandboxClient` и `AsyncSandboxClient`;
- `examples/` — пользовательские сценарии;
- `tests/` — unit- и интеграционные тесты;
- `docs/` — документация MkDocs;
- `.agents/skills/t-invest-python-sdk-bot-builder/` — workflow разработки и ревью
  торговых программ;
- `scripts/generate_models/` — генерация Python-моделей и сервисов;
- `scripts/noxfile.py` — тестовая матрица поддерживаемых версий Python.

## Соглашения SDK

- Новому коду предпочитайте импорты из `t_tech.invest.grpc`.
- Модели запросов можно явно импортировать из
  `t_tech.invest.grpc.schemas`.
- Не используйте устаревшие импорты `tinkoff.invest`.
- Не добавляйте новый код на устаревших сервисах из `t_tech.invest.services`.
- Учитывайте request-обeртки нового API:

  ```python
  response = services.orders.post_order(
      request=PostOrderRequest(
          # Поля сверяйте с моделью текущей версии.
      )
  )
  ```

- Не смешивайте синхронный и асинхронный интерфейсы. Все вызовы
  `AsyncClient` и асинхронных сервисов должны быть `await`-нуты.
- Используйте клиент как контекстный менеджер; значение после `as` — набор
  сервисов.
- Сохраняйте совместимость с минимальной версией Python из `pyproject.toml`.

## Реальный контур и песочница

- `Client` и `AsyncClient` по умолчанию используют реальный API endpoint.
- `SandboxClient` и `AsyncSandboxClient` фиксируют sandbox endpoint.
- Не меняйте выбранный пользователем контур без явного требования.
- Не заменяйте реальный пример песочным и наоборот только из соображений
  стиля: назначение каждого режима описано в
  `docs/ai/real-vs-sandbox.md`.
- Автоматические тесты не должны создавать реальные заявки или изменять
  реальные счета.
- Сетевые sandbox-тесты должны оставаться явно помеченными маркером
  `test_sandbox` и не запускаться как обычные unit-тесты.

## Торговая и финансовая корректность

- Никогда не записывайте токены в код, документацию, фикстуры, логи или
  сообщения об ошибках. Получайте их из переменных окружения.
- Для денег и цен используйте `Decimal`, `Quotation` и `MoneyValue`.
  Преобразуйте `Quotation` штатными `quotation_to_decimal` и
  `decimal_to_quotation`, а `MoneyValue` — `money_to_decimal` и
  `decimal_to_money` из `t_tech.invest.utils`; не собирайте `units` и `nano`
  вручную и не используйте `float` в расчeтах заявок.
- Проверяйте семантику `quantity`: в торговых запросах это обычно количество
  лотов. Размер лота берите из данных инструмента.
- Используйте timezone-aware даты и UTC для API-запросов.
- Не подменяйте `figi`, `instrument_id` и `instrument_uid` друг другом.
  Используйте поле, объявленное в конкретной request-модели.
- Для создаваемой заявки до сетевого вызова сохраняйте уникальный
  `PostOrderRequest.order_id` как клиентский ключ идемпотентности. Не смешивайте
  его с биржевым `PostOrderResponse.order_id`; сохраняйте оба идентификатора.
- Не делайте слепой retry мутаций. После неопределeнной сетевой ошибки сначала
  запросите состояние исходной операции или заявки, передав соответствующий
  тип идентификатора, если его требует request-модель.
- Перед отправкой заявки учитывайте торговый статус, доступность покупки или
  продажи, шаг цены, размер лота, лимиты позиции и доступные средства.
- Стратегия формирует намерение, а проверка риска и отправка заявки должны
  оставаться отдельными детерминированными этапами.

## Генерируемый код

Файлы `*_pb2.py`, `*_pb2_grpc.py` и `*.pyi` в `t_tech/invest/grpc/`
генерируются из proto-файлов и не редактируются вручную.

Модели и сервисные модули, соответствующие proto-файлам, создаются через
`scripts.generate_models`. Для изменения контракта исправьте proto или
генератор и выполните:

```bash
make gen-client
```

Ручные утилиты и интеграционный код внутри `t_tech/invest/grpc/utils/`
изменяйте обычным способом.

## Рабочий процесс

1. Проверьте `git status` и не затирайте пользовательские изменения.
2. Найдите существующий похожий сервис, тест или пример.
3. Сделайте минимальное изменение без несвязанных рефакторингов.
4. Добавьте или обновите тесты пропорционально риску.
5. Обновите документацию при изменении публичного поведения.

Основные команды:

```bash
poetry install -E all
make test-fast
make lint
make check
make docs
nox -f scripts/noxfile.py -- --cov
```

Для небольшого изменения сначала запускайте узкий набор тестов:

```bash
poetry run pytest tests/path/to/test_file.py
```

Если команда недоступна в окружении, явно сообщите об этом и выполните
доступные статические проверки, например `git diff --check`.

## Критерии завершения

- импорты и сигнатуры существуют в текущем коде;
- тесты не обращаются к реальному торговому контуру;
- токены и персональные данные не попали в diff;
- для финансовых значений не добавлен `float`;
- документация различает реальный контур, песочницу и локальные тесты;
- выполненные проверки и ограничения окружения перечислены в отчeте.
