# Реальный контур и песочница

Реальный API и песочница решают разные задачи. Выбор контура не следует
скрывать внутри стратегии или менять автоматически.

## Сравнение

| Сценарий | Что использовать | Причина |
|---|---|---|
| Получение фактических данных реального счёта | `Client`/`AsyncClient`, только необходимые read-методы | песочница не является копией реального счёта |
| Получение актуальных рыночных данных | реальный клиент и read-методы | нужны данные реального рынка |
| Проверка интеграции создания и отмены заявок | `SandboxClient`/`AsyncSandboxClient` | операции не должны затрагивать реальный счёт |
| Детерминированный unit-тест стратегии | локальные моки или фикстуры | тест не зависит от сети и состояния API |
| Бэктест | локальные исторические данные | исключаются случайные сетевые и рыночные изменения |
| Реальная торговля | `Client`/`AsyncClient` только после явного выбора пользователя | заявки могут быть исполнены на бирже |

`Client` сам по себе не означает отправку заявки: через него можно выполнять
read-only запросы. Риск определяется выбранным методом и правами токена.
`read-only` — это политика приложения, а не отдельный endpoint или класс
клиента: зафиксируйте разрешённые методы в конфигурации и запретите мутации в
`RiskManager`/`OrderExecutor`.

## Явное создание клиента

```python
from t_tech.invest.grpc import Client, SandboxClient


def create_services(token: str, mode: str):
    if mode == "production":
        return Client(token)
    if mode == "sandbox":
        return SandboxClient(token)
    raise ValueError(f"Unsupported mode: {mode}")
```

Для асинхронной программы используйте соответствующую пару
`AsyncClient`/`AsyncSandboxClient`, а не условные вызовы `await` поверх
синхронного клиента.

## Правила для LLM

LLM должна:

- явно назвать выбранный режим в плане и инструкции запуска;
- сохранить режим, который запросил пользователь;
- отличать read-only запрос к реальному API от торговой мутации;
- для неоднозначного учебного примера предложить sandbox или локальный mock;
- не считать наличие токена подтверждением реальной сделки;
- не отправлять реальную заявку только потому, что код технически готов;
- вынести переключение режима в конфигурацию, а не определять его по данным
  счёта или тексту рыночного сигнала.

Для реальной мутации должны быть явно определены как минимум счёт,
инструмент, направление, количество лотов, тип заявки, ограничения риска и
правила обработки неопределённого результата запроса.

## Ограничения песочницы

Песочница предназначена для проверки интеграции с API, но не заменяет:

- unit-тесты бизнес-логики;
- бэктест с комиссиями, проскальзыванием и ликвидностью;
- проверку поведения на разрывах соединения;
- риск-контроль реальной торговой системы.

Не переносите вывод о доходности стратегии из песочницы в реальную торговлю
без отдельного тестирования.
